# Governance

## Decision making

Maintainers steward project direction, releases, security, and repository access. Routine decisions are made through
reviewed changes. Decisions with architectural, compatibility, security, or governance impact require a written proposal
and explicit maintainer approval.

## Roles

Contributors propose and implement changes. Reviewers evaluate changes within their expertise. Maintainers merge work,
manage releases, resolve escalations, and enforce repository policies. A person may hold more than one role.

## Principles

- Prefer evidence and documented tradeoffs.
- Record consequential decisions in the repository.
- Require review from someone other than the author for protected branches.
- Apply least privilege to repository and release access.
- Resolve conflicts of interest openly and recuse affected decision makers when appropriate.

## Changes to governance

Governance changes use the normal review process and require explicit maintainer approval. The pull request must explain
the motivation, impact, and transition plan.
