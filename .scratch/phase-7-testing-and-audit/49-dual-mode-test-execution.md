# 49: Dual-mode test execution

**What to build:** the same suite passing two ways — inside a container against service names, and on the
developer's machine against published ports — because a suite that only passes one way hides environment-specific
failures.

**Blocked by:**

- [48](48-integration-test-suite.md)

**Status:** done

**Reverified 2026-09-23:** both modes collected 2,112 tests, then passed 2,089 covered core tests and 23 timing
tests. Container mode took 524.892 seconds, host mode 1,333.515 seconds, and the total was 1,919.697 seconds.

**Audit remediation:** every public task that can select SMTP tests now owns the same temporary Mailpit lifecycle;
skips fail the controller session; exact expected log records no longer become secondary failures when pytest fails;
and any RabbitMQ `global_qos` record remains a blocker.

- [x] The testing stack starts headless, containing only the services the suite needs and no dashboard or UI
      service.
- [x] The suite passes inside the test container, resolving services by container name.
- [x] The suite passes on the host, resolving services at the loopback address and the published ports.
- [x] Both modes report the same number of collected tests. A difference means environment-dependent skipping,
      which hides failures and is a defect to fix, not to accept.
- [x] Both modes meet the coverage threshold.
- [x] One command runs both modes and reports each independently, with distinct exit codes for which mode failed.
- [x] The host-mode environment file is generated by the same tooling as the others, so the two cannot drift.
- [x] The testing stack runs concurrently with the development stack without colliding on any name, volume,
      network, or port.
- [x] Total wall-clock time for the parallel run is recorded, so a later regression in test speed is visible.
- [x] After each mode, testing health and Docker ownership still pass, no test-created process or resource remains,
      and the affected testing and development logs contain no unexplained warning-or-higher record.
